# Golden Baselines for Regression Testing

This directory contains pre-captured golden artifacts for regression tests.
They must be generated **before** any head-tuning refactor and kept immutable afterward.

---

## Files

### `knn_swap_green_red_cube.json` — KNN head-selection golden (Task 6 regression gate)

**What it captures:** The exact head-selection result on the `swap_green_red_cube` task
attention dataset. Originally produced by the legacy `KNN_regression.py` (now removed);
reproducible via the `openpi.head_tuning.select` CLI, which Task 6's regression test gates
against this golden.

**Source command (current CLI):**
```bash
cd /scr2/yusenluo/openpi_robotv
conda run -n openpi python -m openpi.head_tuning.select \
  --attn-h5 temp_data/swap_green_red_cube_pi05_action.h5 \
  --unit-mode head --target 20 \
  --out tests/golden/heads_swap_green_red_cube.json
```
(The `*.txt` / `*.log` files in this directory are gitignored remnants from the original
legacy run; the JSON is the tracked golden the regression test reads.)

**Expected output values (captured 2026-06-24):**
- `cv_mse = 0.021498`  (tolerance: ±1e-4)
- `best_k = 30`
- `trainable_head_indices` = 20 `(layer, head)` pairs listed in the JSON

**Purpose:** Task 6 (`select.py` CLI regression gate) must reproduce these exact values.

**Environment:** conda env `openpi`, no GPU required (CPU-only KNN).

---

### `knn_swap_green_red_cube.txt` — Raw KNN output (supplementary)

The raw text output written by `KNN_regression.py` via `KNN_OUT_TXT`. Stored alongside
the JSON for human readability and debugging.

---

### `knn_swap_run.log` — Full KNN run log (supplementary)

Full stdout+stderr of the KNN run captured via `tee`. Contains per-head MSE rankings for
all 144 heads across k=10,20,30,40.

### `extract_droid_smoke.h5` — Extract golden (Task 7 regression gate)

**What it captures:** Attention activations (`last_token_attn` shape `(18,8,256)` per
frame) generated by the `pi05_droid` policy checkpoint on the `swap_green_red_cube`
task. NOTE: the legacy `generate_activation_dataset_on_robot.py` hardcodes
`MAX_EPISODES = 200` and ignores the `MAX_EPISODES` env var, so it processed all 20
input episodes (~120 MB), not 2. The new `extract.py` (Task 7) adds a working
`--max-episodes` flag; Task 7's regression test compares against this 20-episode golden.

**Tracking:** this `.h5` (~120 MB) and `knn_swap_run.log` are kept on disk only and are
**gitignored** (`tests/golden/*.h5`, `tests/golden/*.log`) — large binaries must not enter
the release repo's git history. Only the JSON/txt/README are tracked.

**Source command:**
```bash
cd /scr2/yusenluo/openpi_robotv
TASK=swap_green_red_cube \
INPUT_H5=temp_data/swap_green_red_cube_20.h5 \
ATTN_H5=tests/golden/extract_droid_smoke.h5 \
conda run -n openpi python src/openpi/generate_activation_dataset_on_robot.py 2>&1
```

**Purpose:** Task 7 (`extract` adapters + CLI regression gate) must reproduce the same
per-frame activations up to floating-point tolerance.

**Environment:** conda env `openpi`, **GPU required** (A6000 or similar; checkpoint
downloaded from `gs://openpi-assets/checkpoints/pi05_droid`). Checkpoint is cached to
`.cache/openpi/openpi-assets/` after first download.

**Checkpoint:** `gs://openpi-assets/checkpoints/pi05_droid` (pi0 DROID model)

## How to Regenerate

If you need to regenerate these goldens (e.g., after an intentional behavior change):

1. Ensure the conda env `openpi` is active and GPUs are available (for extract).
2. Re-run the source commands listed above for each file.
3. Update the JSON values with the new observed `cv_mse`, `best_k`, and `trainable_head_indices`.
4. Commit the new golden files.
5. Update any regression tests (Task 6 / Task 7) that compare against these goldens.

**Do NOT regenerate these files as part of a refactor** — the whole point is to prove
that the refactor does not change behavior.
